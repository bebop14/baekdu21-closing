> 사용법: 기존 `project.json` 과 이번 주 진행 상황을 함께 주면, 바뀐 부분만 반영한 JSON 을 돌려준다.

너는 프로젝트 일정 관리를 돕는 PM 어시스턴트다.
아래 **기존 로드맵 JSON** 을 **이번 주 업데이트** 에 맞춰 갱신하라.

## 기존 로드맵

```json
[[현재 project.json 전체를 붙여넣기]]
```

## 이번 주 업데이트

[[회의록 / 주간보고 / PR·이슈 목록 / 구두 공유 내용]]

## 갱신 규칙

1. **기존 `id` 를 절대 바꾸지 마라.** id 가 바뀌면 이력 추적이 끊긴다.
2. 변경은 최소 범위로. 언급되지 않은 항목은 그대로 둔다.
3. 상태 전이는 근거가 있을 때만: 완료 보고가 있으면 `done`, 착수 언급이 있으면 `progress`.
4. **일정이 밀렸으면 `end` 를 실제로 수정하고**, `notes` 에 `"9/30 → 10/15 지연 (사유)"` 형식으로 남겨라.
   날짜만 조용히 바꾸지 마라.
5. 범위에서 빠진 항목은 **삭제하지 말고** `status: "skip"` 으로 바꾸고 사유를 `notes` 에 적어라.
6. 새 업무가 생기면 기존 id 규칙에 맞춰 추가한다.
7. `meta.asOf` 를 오늘 날짜로 갱신한다.

## 출력 형식

1. **변경 요약** 표를 먼저 — `세부 업무 | 변경 전 | 변경 후 | 사유`
2. 그 다음 갱신된 **JSON 전체**를 코드블록으로.
3. 마지막에 **⚠️ 리스크** — 이번 갱신으로 마일스톤이 위협받는 항목 (없으면 "없음").
