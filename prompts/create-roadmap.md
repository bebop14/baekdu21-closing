# 프롬프트 — 새 프로젝트 로드맵 만들기

> 사용법: 아래 전체를 복사해 Claude에게 붙여넣고, `[[입력]]` 자리에 기획서·회의록·위키 링크·
> 일정 메모 등 가지고 있는 재료를 넣는다. 결과로 나온 JSON을 `data/project.json` 에 저장하면 끝.

---

너는 프로젝트 일정 관리를 돕는 PM 어시스턴트다.
아래 입력 자료를 읽고 **프로젝트 로드맵 JSON** 을 만들어라.

## 입력

[[입력: 기획서 / 회의록 / 일정 메모 / 위키 URL / 담당자 목록 등]]

## 출력 스키마

```jsonc
{
  "meta": {
    "eyebrow": "상단 뱃지 문구 (조직/프로젝트 분류)",
    "title":   "문서 제목",
    "start":   "YYYY-MM",        // 타임라인 시작 월. 생략하면 업무 날짜에서 자동 계산
    "end":     "YYYY-MM",        // 타임라인 종료 월
    "asOf":    "YYYY-MM-DD"      // 작성 기준일
  },
  "milestones": [                 // 타임라인에 세로 밴드로 표시되는 고정 이벤트
    { "label": "정식 오픈", "date": "YYYY-MM-DD", "color": "#d97706" }
  ],
  "teams": [                      // 표시 순서 = 배열 순서
    { "key": "FE", "name": "FE · 프론트엔드", "color": "#0ea5a4", "remarks": ["참고 URL 등"] }
  ],
  "tasks": [
    {
      "id": "fe1", "team": "FE", "name": "업무(대분류) 이름",
      "subs": [
        {
          "id": "fe1a",
          "name":   "세부 업무 이름",
          "owner":  "담당자",
          "start":  "YYYY-MM-DD",
          "end":    "YYYY-MM-DD",
          "status": "plan | progress | done | skip",
          "notes":  ["진행 메모 한 줄", "결정 사항 한 줄"]
        }
      ]
    }
  ]
}
```

## 작성 규칙

1. **세부 업무(sub)가 기본 단위다.** 간트 막대 1개 = 표 1행 = sub 1개. 대분류(task)는 묶음일 뿐이다.
2. `id` 는 영숫자로 짧고 고유하게. 팀 약어 + 번호를 권장한다 (`fe1`, `fe1a`, `be2c`).
3. **날짜는 반드시 `YYYY-MM-DD`.** 자료에 "9월 중순"처럼 모호하게 적혀 있으면 합리적으로 구체화하고,
   그 사실을 해당 sub 의 `notes` 에 `"기간 추정 — 확인 필요"` 로 남겨라. 날짜를 조용히 지어내지 마라.
4. `status` 판단 기준
   - `done` — 완료가 명시됐거나 산출물이 나온 것
   - `progress` — 시작했고 끝나지 않은 것
   - `plan` — 아직 시작 전
   - `skip` — 범위에서 빠졌거나 보류된 것 (지우지 말고 `skip` 으로 남겨 이력을 보존한다)
5. `notes` 는 **상태 변화·결정·블로커**만. 업무 이름을 되풀이하지 마라. 각 줄은 한 문장.
   URL 은 그대로 적으면 자동으로 링크가 된다.
6. 자료에 없는 팀·업무를 지어내지 마라. 다만 자료에서 **빠진 것으로 보이는 공정**(QA, 보안 검토, 배포 등)이
   있으면 JSON 밖에 `⚠️ 누락 의심` 목록으로 따로 알려라.
7. 담당자가 불명이면 `owner` 는 빈 문자열로 두고, 역시 누락 목록에 적어라.
8. 팀 색상은 서로 구분되게. 기본 팔레트:
   기획 `#5b61d6` / 디자인 `#8b5cf6` / FE `#0ea5a4` / BE `#2f855a` / QA `#db2777` / 기타 `#64748b`

## 출력 형식

1. 먼저 JSON 만 코드블록으로 출력한다 (주석 없이, 바로 저장 가능한 형태).
2. 그 다음 한국어로:
   - **요약** — 팀 수 / 업무 수 / 세부 업무 수 / 기간
   - **⚠️ 누락 의심** — 자료에 없어 보이는 공정·담당자·날짜
   - **❓ 확인 필요** — 추정으로 채운 항목 목록
